# Body engine (MVP)

The engine that runs one Minecraft body. ClojureScript owns behaviour and state (jobs, triggers, scheduler,
memory, planner). JavaScript is the mineflayer layer ("primitives") and a few thin adapters (sockets, rendering).

How the parts fit:

- A **body** is one mineflayer bot plus one engine process (`engine.main`).
- **Primitives** are the only way to sense or act on the bot. Sensing is sync and cheap. Acting is async and needs an
  ownership token.
- A **job** is a goal-achiever: a namespace with a `check` (can it usefully run now?) and a `round` (do one bounded piece).
  Jobs compose through job expressions (`seq`, `any`, `repeat`, `until`, `hold`) and call child jobs.
- A **trigger** is an exception handler: when its condition holds, the register fires a one-off **reflex job**, which cuts
  whatever is running. Jobs are goals; triggers are reflexes. Never mix the two.
- The **scheduler** ticks every 250 ms, picks the next round, and cuts by rotating the ownership token.
- **Memory** is one EDN store per body. **Events** are an EDN log with a local HTTP API. Agents use small CLI tools on top.
- **Zones and claims** are social rules that jobs consult. The engine never enforces them.
- **Sensing like a player**: tools and jobs only report what a normal player could see or hear (no x-ray, no entities
  through walls).

## Toolchain and commands

shadow-cljs 3.5.4 (ClojureScript 1.12.145). Async code uses `^:async` functions with `await`; promesa is not used.
`await` works inside `let`, `loop`/`recur`, `cond` and `try` of an `^:async` fn, but not inside a nested `fn`. An anonymous
async fn needs a name: `(fn ^:async round [ctx] ...)` compiles, `^:async (fn ...)` does not. Prefer `(defn ^:async foo-round [ctx] ...)`.

## Primitives

`createPrimitives({host, port, username, auth})` (resolves once spawned and the column under the body is loaded, up to
10 s) and `createPrimitivesFromBot(bot, {timeScale})` (for tests) return a `primitives` object. The cljs side calls it
through interop, for example `(.moveTo p token #js {:pos #js {:x 1 :y 64 :z 2}})`. JS values are read with `.-field` or `aget`.

### Conventions

- Positions are `{x, y, z}`; block positions are integers. Item and block names are registry names without namespace.
- Every acting method is `async name(token, args)` and resolves to an object with a `status` string. A domain failure is a
  status, never a rejection. A mineflayer error inside an acting call resolves `{status: 'failed', reason}`.
- Rejections happen only for a cut (`err.code === 'cut'`) and for bad args (`'bad-args'`).
- Time bounds are hard: a method that reaches its bound stops and resolves `timeout` (or `partial` for `moveTo`). A `timeout` after the stacks changed carries `inventoryChange` `{item: delta}`: `trade` and `enchant` read it, the others re-read the inventory.
- Sensing methods are synchronous, take no token, and are cheap (scans are bounded by radius and `max`).
- Primitives do not walk. Reach for `dig`, `place`, `transfer`, `sleep`, `attack` etc. is the caller's job (`moveTo` first).

### Ownership token

`setOwner(token)` is called by the engine before each round with a fresh token. Jobs reach primitives only through `ctx/act`.
A call with a stale token rejects at once with `cut`. When the owner changes, every in-flight call of the old token stops
within one game tick (goal cleared, `stopDigging`, window closed, controls released) and rejects with `cut`. `null` means
nobody may act. `isOwner(token)` reports whether a token is current.

### Sensing (sync, no token)

| method | returns |
|---|---|
| `self()` | `{username, pos, health, food, foodSaturation, oxygen, onFire, inWater, inLava, onGround, chunkLoaded, settling, isSleeping, vehicle, effects, experience, dimension, timeOfDay, isDay, raining, thundering, players, held, equipment, inventory}` |
| `worldAge()` | the world age in game ticks (`null` offline); a cheap read of what `self()` carries, used for memory `:age` |
| `entities({radius=16, kind?, names?, ids?, max=32})` | `[{id, name, kind, pos, distance, visible?, ...}]` by distance; `kind` is `hostile`, `passive`, `player`, `item` or `other`; passive mobs and villagers are listed only with a clear line of sight and inside the view cone or within hearing (`senses/in-view?`, the rule of `sense-thing`: a cow behind the body beyond earshot is not listed); hostiles, items and players are listed regardless and carry `visible` (an item, silent, also needs the cone) (a player counts as `sleeping` only in sight) |
| `blockAt(pos)` | with perception, `sensedAt(pos)`: the cell as the body senses it (an unknown cell has no `name`), `null` when the chunk is not loaded; jobs and triggers read through `jobs.lib.util`, never `.blockAt` (lint) |

Notes:

- `health` and `food` are 0..20. `equipment` is `{head, torso, legs, feet, offHand, mainHand}`, each `null` or
  `{name, count, durability?, enchants?: [{name, level}]}`. `inventory` is main and hotbar only: `[{name, count, slot}]`. `effects` are
  `[{name, amplifier, duration, left}]` with snake_case names; `duration` is the packet's, `left` the ticks remaining since it arrived (-1 infinite). `vehicle` is `{id, uuid, name}` or `null` (`js/vehicle.mjs` repairs
  mineflayer's stale `bot.vehicle` and moves riders with their mount). `engine.senses` derives `isDay` (`timeOfDay < 12542 || > 23460`), `raining` (rain level above 0.2) and `thundering` (above 0.9 while raining) from the raw `timeOfDay`, `rainState`, `thunderState`, and flips `weather-changed` from the raw `weather-levels` event.
- `chunkLoaded` false means the column under the body is not loaded (physics then emits no tick). `settling` is true while
  the body is connected but its senses are not yet trustworthy.
- Entities: items carry `item {name, count}`; players `username`, `sleeping` (only in sight); mobs `uuid`, `baby`, villagers `profession` (`unemployed` when none), sheep `color` and `sheared`; leashed
  mobs `leashed`, `leashedToMe`, `leashHolder`; riders `passengers` and `vehicle`. Creepers carry `creeper: true`. Every
  hostile carries `visible` (`engine.senses` over the raw world: a raycast from the eye to the entity's middle, then its head, then the head-height corners of its box, any one clear, the answer kept while the eye, the raw world's epoch and the entity's box stay the same; glass, fences, gates, iron bars, water, fire and the like do not block, a door or slab only where the line meets it, an
  unloaded cell never blocks). Raw entity lists go through `js/live-entities.mjs` (drops bare, never-spawned entities, picked-up drops and mobs that died; an item's `spawn` record: time, place, nearest player, the body's last toss). Every turn of the head goes through `js/gaze.mjs`: a look that would meet the eyes of an enderman in line of sight keeps its yaw and moves its pitch the least it must (also each physics tick, and a dismount's look); an enderman's entity carries `angry` (metadata `creepy`), and a calm one is no danger (`danger/calm-enderman?`).
- Blocks carry `age` for crops (wheat/carrots/potatoes ripe at 7, beetroots 3, sweet berries from 2) and, with
  `properties`, every block state (integers as numbers, booleans and enum names as they are).
- **Hostile trigger rule.** `:hostile-near` holds only for a real danger within its radius (`jobs.lib.danger/danger?`): a
  melee mob the body knows of that has a walkable way to the body, or a ranged mob (skeleton and the like) with a line of
  fire, both read over the blocks the body has seen, a cell it has not seen a way for the mob and a gap for an arrow
  (`reach/mob-lookup`, `reach/arrow-lookup`) (in closed quarters, `danger/closed-quarters?`: a tunnel, or a roof and walls three ways within 3 (`::quarters-reach`), it must be seen, not only heard; heard only, a ranged mob counts in the near band, 8 blocks, alone). A drowned holding a trident (the `held` field of a hostile in `entities()`) is ranged. A drowned in water is judged from the surface of its water column (it swims up). A mob walled in or fenced in (fences, walls and shut gates are 1.5 high, never stepped onto), across a deep trench, or with the body sealed in is no danger, unless its blow hurt the body within `danger/::hit-s` (5 s): it reached the body. Room checks (`reach.room`) take an explicit `unseen` arg for a cell the body has not seen: `:solid`/`:fill` for "would this fill shut me in?" (a wall), `:ground` for "am I sheltered?" (open ground); "can this walk get out?" reads as the walk's plans do (`wworld/unseen-kind`: `:raw` under go-to `:unknown false`, else the buried body's rock guess and the cells looked at and not seen a wall, the rest open ground). "Knows of" comes from perception's
  mob memory (`engine.perception`): heard within 16 blocks (not a silent creeper), or seen (clear line, within 48, in the
  view cone or heard, and lit; in the dark only within 4). A creeper with a lit fuse hisses (`fusing`), is heard and is always a danger (it swells only with a line of sight within 7). A heard
  mob is judged at its rough spot (direction, band: near 4, far 16, derived from `obs/near-band`; `danger/mob-pos`, `mob-distance`), never its exact place; outside or in a large cave a heard melee one counts as seen; in closed quarters it counts only once seen (a heard mob in clear, lit sight is seen, so a look finds nothing more) or heard within 2 (`::close-hearing`) when a mob could stand beside the body that way, within 45 degrees (it hits across a corner it cannot walk round). `retreat` and `respond-to-hostile` use the
  same danger rules.
  A hostile that cannot hurt the body firing the response is a trigger bug, not a job bug.

stop at the first failure. `swim` without `toward` holds jump until the eyes (1.62 up, not the head top) are out of water, ending `blocked` when the body rises no higher with a ceiling over it for `prim/swim-blocked-ms` (300); with `toward` it climbs out
onto a rim; with `tread` it then keeps jump held for the rest of `ms` (ends `timeout`). Every bound bot has collision half-width 5079/16384, just under 0.31 (0.3 left the body flush against block faces and rejected every move), and a collision clip with a tolerance of 1e-7 on every axis (`js/clip-tolerance.mjs`: a box a rounding step into a face is held at it). The engine's physical constants (body widths, height, eye height, step height, gravity, the clip tolerance, the hostiles' chase speeds) are in `src/engine/constants.json`, the one copy: cljs reads it through `engine.constants`, the JS side imports the file.
Acting while asleep first leaves the bed.

**Offline is body state.** `offline` quits the bot, emits `offline`, waits `ms`, reconnects with the same params (3 tries),
rebinds the library bot, emits `online`. While offline: `self()` is `{status: 'offline'}`, `entities` returns `[]`,
`blockAt` returns `null`, `isOffline()` is true, the register and list are paused (no trigger evaluated, no round
started), and acting calls resolve `{status: 'offline'}`. A cut ends the wait early but the body reconnects first. A round that throws while the body is offline is cut, not failed (the job stays listed). `close()`
cancels it. Only `createPrimitives` supports it. The engine records why in its `:away` atom (`engine.core/away`); a
log-out (`jobs.survival.log-out`) gives `:why`, otherwise it is `:connection-lost`. `lastKnown()` is the position, health, food, inventory and equipment `self()` read just
before the body left (null online); offline status and inventory show it marked `:last-known`.

An unplanned disconnect (kick, socket end, restart) emits `disconnected` and reconnects by itself: one try, then after
each failure a `reconnect-failed` event and a wait of 1 s doubling up to 60 s, until `online` or `close()`. A bot `error`
is emitted as a body event, never thrown. The engine turns an act's `offline` into a cut; the job stays listed.

The pathfinder goal never outlives a walk, and death and respawn clear it, and a respawn clears the fire, lava, water and air state the body died with. The pathfinder's movements (`js/movements.mjs`)
never dig or build; hazards (powder snow, cobweb, magma, campfires) add cost, and fire and lava are avoided outright.

### Body events

`primitives.onBodyEvent(listener)` delivers `{kind, ...}` objects: `hurt` (health, food, amount, cause, attacker), `died`
(pos, inventory, experience, cause: lava/fire/void from the block, else the lethal hit's attacker or damage type; `atJoin` for a death the server dealt while the client hung or dropped, read when the fresh bot logs in dead: the old bot's last pack, then `respawned`), `respawned`, `chat`, `picked-up` (`own` when it follows the body's own dig, use or transfer, or is its own toss picked up again), `woke`, `player-joined`/`player-left`, `weather-changed` (raining, thundering), `spawned`,
`disconnected`, `error`, `reconnect-failed`, `world-not-loaded`, `physics-stalled`, `offline`, `online`, `sleep-status`
(the action bar's sleep count: `sleeping`, `needed`, or `skipping`), `spawn-set` (pos; the "Respawn point set" line) and `spawn-reset` (the bed is gone). The engine
turns each into a body-memory entry of that kind. `hurt` events are merged into one per second in the event log. A death
drops every listed job (cancelled `:by :death`) but those submitted with `:survive-death?` (a running one is cut, memory
kept; the `died` event's `:survived` names them; the job reads `(ctx/latest c :died)` to judge whether its memory still holds)
and every reflex job; register entries stay, so a trigger that still holds (`died` starts recover-drops) runs its job
again. A kept job starts again only after the respawn.

## Jobs

A job is a namespace under `src/jobs/` exporting `round` (and `can-start?`, `can-run?`, each defaulting to `:ok`; Contract jobs below), and optionally `doc`, `args` and `idle-ok` (`true`: its acts are no work, see
`body.idle`). The namespace follows the path (`src/jobs/forestry/fell_tree.cljs` is `jobs.forestry.fell-tree`).
`(def meta {:category :phase :part-of '[jobs.survival.night]})` is read at compile time: `:category` is `:goal` (default), `:phase`, `:reflex` or `:debug` (default for `jobs.debug.*`); `catalog jobs --category` lists one kind. `:tags [:mine :light]` (resource or goal words, in the job file) add to the tags the catalog derives itself (the family and the words of the name); `catalog jobs --tag mine` lists the jobs with that tag. `:goal` marks a job an agent submits for a goal (it fetches its needs); a bare `catalog jobs` lists those with their doc's first sentence, the other jobs by family, and counts phase, reflex and primitive jobs (`--all` names them). `:position-bound? true` marks a job whose meaning depends on where the body stands: the agent tool stamps its submit with `:submitted-at`. `:own-tries? true` marks a job that counts its own tries (`ctx/book-try!`): its children's endings are not booked on its frame's `:tries` line (go-to).

```clojure
(ns jobs.survival.eat
  (:require [engine.args :as a]
            [engine.ctx :as ctx]))

(def doc "Eat the best food carried.")                       ; optional
(a/defargs args                                              ; optional
  {:item {:doc "the food to eat" :default nil :spec a/item?}})
(defn ^:async round [c]                                      ; ctx -> :continue | an ending (ctx/end)
  (await (ctx/act c :eat #js {}))
  (ctx/end c :done nil))
```

**Args.** `engine.args/defargs` declares args as cljs.spec: every arg has a `:spec`, a predicate of `engine.args` (`int-in`, `num-in`, `pos-num?`, `item?`, `name?`, `position?`, `box?`, `coll-of`, `set-of`, `map-of`, `map-with`, `or-of`, `valid-by`), a set of the allowed values, a core predicate (`boolean?`, `string?`, `keyword?`, `map?` ...) or `::a/pos` (`[x y z]` or `{:x :y :z}`, conformed to `{:x :y :z}`). A group `{:doc :keys {k entry}}` is a nested map of args; a caller's group merges over its defaults key by key. nil = unset. At submit undeclared keys are refused at every level, then the args are conformed; a misfit is refused as one line naming job, key path, what the spec wants and the value (`jobs.x :risk :min-health must be a whole number from 1 to 20, got 30`). A child call (`ctx/call-child`) and a restore conform the same way. A predicate built with `a/pred` carries its want text; the catalog shows each `:spec` as that text. `(a/declare! sym data)` registers a hand-built job's args (tests).

There is no catalog to edit: adding the file adds the job. `engine.registry/jobs` is `{ns-symbol {:can-start? :round :doc :args}}`,
built at compile time. The build hook `engine.build-hooks/add-job-namespaces` lists every file under `jobs`
that defines `round` and no old `check`, or `round` and `can-start?` or `can-run?` (others are helpers), fails the compile when such a file's `ns` does not match its
path, a file defines `round` and `check` but none of those, or a job lacks `safe?` or `fit?` (the message names the job and the missing export), and the macro `engine.registry/job-registry` emits the map, with each `engine.primitive` table entry as the job `jobs.primitive.<kebab-case>` (`jobs.primitive.move-to`: one act, the act's args; a failed act's ending text names its status, the block that holds the cell and its reason; each table entry names its failure statuses and their kinds (`:fails`; `any-act-fails` adds the ones every act can return), a status missing there ends nothing-possible, and a JS test fails on one the sources return; each arg has a typed spec in `jobs.primitive/arg-specs`). The exports must be top-level `def`/`defn` forms, and a job must not
require `engine.registry`.

- **round**: returns `:continue` or an ending (`ctx/end`, Contract jobs below; the job leaves the list, its memory is
  deleted). Anything else, or a throw, is a failure: the job stays listed, marked failed, with a `job.failed` warn, and
  the scheduler skips it until `retry!` clears the mark. A reflex job that fails is dropped. A cut is never a failure.
- A round works at its goal for as long as it can do useful work; `:continue` means yield (nothing useful to do now,
  e.g. waiting for crops or daylight), not "next step". An intentional pause is a `jobs.time.noop` child (`child/pause!`); it counts against the job's budget.
- **next calls**: an ending other than done of `items.obtain`, `items.get-kit`, `build.from-plan`, `build.pen`, `farm.grow`, `animals.bring` and `animals.breed` carries `:next` (`jobs.lib.next-call`): up to 3 calls `{:job :args}` that would unblock it, then the job again (`:again true`, its non-default args); obtain's no-source check cause carries the unblocking call too. `observe --wait` and `progress --wait` print them as specs to submit.
- **args**: `(a/defargs args {key {:doc :default :spec}})` (Args above); the engine merges the call's args over the defaults, which are the spec's under the settings overlay `:engine.settings/job-args` (below). Undeclared keys are refused.

### Job expressions

Wherever a job is named (scenarios, register entries, `submit!`, `do-now!`, the CLI) it is an EDN list, parsed by
`engine.expr` and never evaluated:

| form | meaning |
|---|---|
| `(jobs.survival.eat {:item "bread"})` | a leaf: the job namespace with optional args |
| `(seq e1 e2 ...)` | run children in order, one child round per round |
| `(any e1 e2 ...)` | each round, call the first child that would not wait |
| `(repeat e)` | when the child is done, start it fresh; never done; a child done `:already` (a `seq` whose children all were, an `any` whose child was) is not counted and rests |
| `(repeat n e)` | the same, done after `n` runs |
| `(until g e)` | repeat `e`; done at the top of a round once `g` would not wait (`g` never runs), e.g. `(until (jobs.time.wait-for-light) e)` |
| a refused child | combinators are contract jobs calling children with `ctx/call`; a child ending other than `:done` ends `seq` with its kind and cause (the child's ending as `:because`); `any` skips it and tries the next, ending as the last refusal; `repeat` and `until` end so only when it was impossible or cut off (or in a reflex job), else rest (`:engine.composite/rest-s` 30 s, doubled for each such run in a row up to `rest-max-s` 600 s; wait `:resting`, declared by the round that starts the rest, so it is never a silent round) and run it again. A child that would wait is not called: a combinator's `can-run?` gives that child's status with its `:slot`, so a listed combinator waits with it, a reflex one ends `:condition-failed`, a `:never` ends it `:impossible` |

An unknown symbol, a wrong arity, an undeclared arg, a bad position arg (`[x y z]` or `{:x :y :z}`)
is refused at load with a message naming the spec. Specs are limited to 256 nodes and depth 24. Memory nests by child
slot (`:c0`, `:c1`, ...). Events name a job by its label (`jobs.forestry.fell-tree`, `(seq jobs.a (repeat jobs.b))`).

## Settings

Tuning numbers live in one global map, read by anyone. A namespace under `jobs/` or `triggers/` declares its keys in a top-level `(a/defargs settings {::wait-ms {:default 5000 :doc "..." :spec (a/int-in 0 nil)}})` (engine.args, as job args; a bad value is refused with `(a/problem k v)`; the key's namespace is the declaring one, `:engine.<area>/<name>` in `engine.settings`). `engine.registry/settings` gathers them at compile time, helper files included. The engine's own keys (`:engine.perception/`, `lease`, `events`, `event-api`, `backoff`, `hurt`, `entities`) sit in the `settings` of their namespaces under `engine/`; `engine.settings-registry/settings` gathers them at compile time and `engine.main` adds its own (the vanilla facts hit range and the sleep monster box are plain constants in `engine.senses`); `(perception/defaults)` and `(backoff/defaults)` read them at use.

- Read `(settings/get settings ::wait-ms)` with the namespace's own map (a typo throws); never inside a top-level `def`.
- Layers, low to high: the code `:default`, `worlds/<world>/settings.edn` (`:world`), `worlds/<world>/agents/<Name>/settings.edn` (`:body`). Files are EDN maps `{key value}`, read at body start (`settings/load!` again reloads).
- A bad value, unknown key or unreadable file keeps the lower layer and emits one `settings.bad` `:info` event naming the key and file.
- `:engine.settings/job-args {jobs.movement.go-to {:min-health 14}}` (world and body files merge per job and arg) overlays any job's arg defaults; an unknown job or arg or a value the arg spec refuses is dropped with a `settings.bad` `:info`. A call's own arg wins. Defaults are frozen into a job's args at submit: a change reaches jobs submitted after the reload; queued, running and restored ones keep theirs.
- A call's `:settings {key value}` (a call key like `:spend`; each a declared setting, value checked against its spec, else refused at submit) overrides that setting for the job's run and the jobs it calls (`settings/scoped`, an `AsyncLocalStorage` scope that follows the awaits), over world and body. A child's own `:settings` win below it.
- `(settings/resolved)` gives `{key {:value :layer :doc}}`. One body per process: `load!` throws for a second one. Tests wrap in `settings/with-settings {key value} f`.
- The JS primitives' tuning numbers (`:prim/*`, `:use-on/*`, `:trade/*`, `:enchant/*`, `:interact/*`, `:vehicle/*`, `:steer/*`, `:raw-world/*`) are declared once as plain data in `js/settings.mjs` (`SPECS`); `settings/js-specs` merges them in at start. A primitive reads `setting('prim/poll-ms')` at use (main hands `createPrimitives` the live reader `opts.settings`; with none the spec default answers), so a reload reaches JS at its next call. Protocol and format facts stay constants.
- Rates: the **game rate** (`(settings/game-rate)`, `frozen?`, `rate-source`) is the server's `/tick rate`, read from `set_ticking_state` by `js/game-clock.mjs`, attached in `connectBot` before spawn so the join packet counts, and independent of the physics shim; with no packet it is 20, source `:assumed`, and one `game-rate.assumed` `:info` is emitted. Game ticks (item despawn 6000, smelting, the night) become ms with `ticks->ms` / `ms->ticks`, re-read at each use. The **physics step** is `(settings/physics-ms p)`: the shim's interval, else 50. Wall-clock timers (engine tick, JS time scale) are never converted. Memory entries and views carry `:age`, the world age in game ticks (still while the tick is frozen); drop timers count it.

## Memory

One EDN store per body: `worlds/<world>/agents/<name>/engine/memory.edn`, `{:entries {kind [entry]} :policies {kind policy}}`. The engine rewrites it only when the swept data changed since the last write (always on stop); the saves around each act write at most once per `::memory-save-ms` (2 s), housekeeping flushes what they skipped, job start/end and a cut write at once, and so does the next act save after a write whose policy has `:durable? true` (the scaffold ledger, the replant debt).

- An **entry** is `{:t wall-clock-ms :wt world-time :age world-ticks :data ...}` (`:age` when known), newest last. **Kinds** are an open vocabulary: `:hurt`, `:died`,
  `:chat`, `:restart`, `:bed`, `:chest`, `:home`, `:looked`, `:moved`, `:picked-up`, `:fed`, `:slept`, `:shelter`, `:threat`,
  `:tidy`, `:scaffold`, `:built-cells` (cells the body placed a block in; a pen it fenced itself is its own), `:forestry/replant`, `:job/j7`, and so on. Body events become entries of their kind; every start
  appends `:restart`.
- **Policy** `{:cap n :ttl ms}` is stored beside the kind. A new kind gets cap 50 and ttl one hour unless a write gives
  one; `:forever` is a keyword; the cap drops the oldest.
- **Sweep** on boot, every `:sweep-ms` (60 s) and before every save: drops expired entries and `:job/<id>` kinds whose
  instance is not live. Saves happen around every `act`, at every round end and whenever the engine writes.
- **Reads** (`engine.memory`) take a view `{:data :now}` and are time-filtered: `entries`, `latest`, `since`, `count-in`,
  `place`.
- **Job memory**: a listed (or running reflex) instance owns kind `:job/<id>`, cap 1, forever, deleted on done, cancel or
  drop. Its data is `{:args ... :children {slot child-map}}` plus the job's own keys.
- **Named places** (`jobs.lib.places`): a place is a kind named after it (`:bed`, `:chest`, `:home`, `:food-source`, or a name
  of 1 to 32 lowercase letters, digits, dashes) with one `{:pos {:x :y :z}}` entry, cap 1, forever. `jobs.memory.set-place`
  records, moves or verifies one; `jobs.memory.forget-place` removes one. `jobs.survival.sleep` and `jobs.storage.deposit`
  record the bed or chest they used when none is recorded; they never overwrite a live different one (a recorded `:bed` farther than the urgent bed radius is replaced).
  The memory layer (`engine.core.notices`, in the ctx's `remember!`/`forget-where!`) emits the info notice for every place or `:reserve` write, whoever made it: `place.set` (`:auto true` unless set-place wrote it), `place.forgotten`, `reserve.set`, `reserve.cleared`; `jobs.memory.remember` earns `memory.remembered`. The memory jobs emit nothing; their endings carry the result.
- **Deaths**: engine core adds one `:deaths` entry `{:pos :dimension :cause :death-t}` per `:died` event, in any mode (cap 10, forever).
  Jobs read it with `(ctx/entries c :deaths)`; a death the body was offline for is not listed.

## Triggers and the register

A trigger is a plain fn `(fn [world view args plans live] truthy-or-level)` (view is a memory view, args the entry's). The default
trigger set `src/triggers/defaults.edn` names each by id; `engine.triggers/all` is built from it at compile time, so a new
trigger is a fn plus one line:

```clojure
{:id :hostile-near :when triggers.survival.hostile-near/hostile-near   ; the fn
 :job (jobs.survival.respond-to-hostile)                             ; default job spec
 :args triggers.survival.hostile-near/defaults                         ; a map or a var, merged under the entry's :args
 :level :danger                                                       ; :danger | :urgent | :comfort (the scheduler, sections)
 :persistence :retry}                                                ; :retry | :cooldown (with :cooldown-s) | :stop
```

The **register** is an ordered vector of entries `{:id :trigger :job :args :persistence :cooldown-s :level :backoff :builtin?}`.
Each tick the engine fires the first entry whose `:when` holds, which is not muted or cooling down and whose job would start: its `can-start?`, `can-run?`, `safe?` and `fit?` say neither `:later` nor `:never` (a held trigger's checks are asked again only after `::held-recheck-ms`, 2 s). A reflex job that ends `condition-failed` (a :look turned :later) holds its trigger the same way. A held reason with `:recheck-after-ms` (a dark place: seconds to light) is not asked again before then. A trigger held by them cuts nothing; `GET /triggers` shows `:held` with the reason, and info `reflex.held` tells it once per reason.

- A firing reflex cuts a running listed job (which stays listed and runs again once no reflex holds the body). It cuts a
  running reflex job only if it sits above that one. A reflex whose job is running does not fire again.
- A reflex job runs one round. Its checks are asked before it fires (above), never again once it runs. A `:continue` counts as `:declined`
  (warn `reflex.continued`, once per reflex an hour). On `:done`, `:declined` (also an info `reflex.declined`) or a throw it is removed. If the trigger
  still holds it fires again as a new instance, subject to persistence. So a reflex job must return `:done` or `:declined`
  at the top of its round when there is nothing to do. Combinators follow this: `any`, `seq` and `repeat` return `:declined`
  when the relevant child declines.
- A reflex job cut by a higher reflex is dropped with its job memory, unless it is in its cleanup: then it is paused
  and resumes (before the list, first by register order; its entry does not fire again meanwhile) once no reflex holds the body. What it must not lose lives in body memory
  (recover-drops' `:recover-trip`, recover's `:hurt`, the shelter's `:shelter`).
- **Persistence**, when the trigger still holds as the job ends: `:retry` fires again next tick; `:cooldown` waits
  `:cooldown-s` counted from the job end; `:stop` waits until the condition has been false once. A `:comfort` `:cooldown` reflex that fired at `:comfort` and is cut off rests its cooldown from the cut (an urgent firing, e.g. starving `:hungry`, does not). An entry's own values
  override the trigger's. A contract job ending `:impossible` stops the entry as `:stop` does, whatever its persistence;
  `reflex.ended` carries the ending's `:kind` and its data. An entry's `:job` may carry call keys (`:spend`, `:ways`).
- **Settling**: after a login, reconnect, respawn or teleport (a forced move over 16 blocks) no trigger is evaluated until
  `settleMs` (1 s) after the column under the body loads. A reflex that ends meanwhile is judged on the first ready tick.
- Agent-only edits (`engine.core`): `register-reflex!`, `remove-reflex!` (not built-ins), `mute!` (with TTL; TTLs run on wall time minus host suspends, `core/ttl-now`, lag saved as state `:clock-lag`), `move!`
  (`{:above id}`/`{:below id}`), `clear-change!`. A change expires back to the default and emits `reflex.reverted`.

### Conditions

An ad hoc `:when` can be a condition: an EDN list `engine.condition/compile` maps onto the library `defaults.edn`
names (`:library`, `jobs.lib.cond`), never evaluated; only library names and literals.

```clojure
(and (not (in-water)) (< (inventory "bread") 8) (because :day-not-come (daytime)))
(not (known? (place :home)))
(or (not (known? (since :bred-cows))) (> (since :bred-cows) 1200))
```

- Every check gives a status (Contract jobs). The trigger holds on `:ok`; `GET /triggers?id=` shows the status, every
  part in `:parts`.
- Values: `(health) (food) (inventory "item") (free-slots) (distance-to pos) (blocks-near "name" r)` (seen blocks only,
  read once a tick) `(since :kind) (time-of-day)`, a position `(place :kind)`; comparisons `< > <= >= =` make them a status
  (`"inventory bread 9 >= 8"`, reason the value's name). `(since :kind)`: seconds since memory last recorded an
  unexpired entry of that kind.
- Statuses: `(daytime) (mounted) (in-water) (hostile-near r)` (a real danger) `(burning) (suffocating) (night-unsafe)
  (wearing "item")`; each has an ok and a fail reason (`(mounted)`: `:mounted` / `:not-aboard`).
- `(and ...)`: any `:never`, else the first `:later`, else the first `:look`, else `:ok`. `(or ...)`: the first `:ok`,
  else `:look`, `:later`, `:never`. Both ask every part. `(not a)` swaps `:ok` and a definite `:later`/`:never`, keeping
  a's text and reason. `(because :reason "text"? a)` renames a failing reason.
- Unknown (offline, no such place) is `[:later "... not known" {:unknown true}]`, which `not` keeps; `(known? x)` is
  definite.
- Job code calls the same fns: `(cond/and (cond/< (cond/health) 7) (cond/not (cond/mounted)))` is a fn of the ctx.
- `compile` validates once at registration; a bad form is refused as data `{:ok false :reason :at :message :allowed}`.

## The scheduler

`tick!` runs every 250 ms:

1. Expire register changes; sweep memory when due.
2. Evaluate the register. The first firing entry that preempts the holder and is not held off by its section cuts by
   rotating the token and runs a round of its job.
3. Otherwise, if a round is in flight, nothing.
4. Otherwise the list: a holding job runs if its check passes (else the others run until it does); else a cancelled job owing its cleanup; else the cut job if its check passes;
   else round-robin from the job after the last one run, to the next whose check passes. If every check declines, nothing
   runs until the next tick.

**Sections and levels.** Each trigger has a level (`:level`, else `:danger`); its `:when` may return a level instead of
true, read every tick (hungry is `:urgent` at food 2 or low health); an entry's own `:level` is a floor the returned level never goes below. While the running round is inside a `ctx/atomic`
section, an entry at or below the section's level (nested: the highest) waits, info `reflex.deferred`, until the section
ends or it has waited `:engine.core.schedule/urgent-wait-s` (15) or `comfort-wait-s` (90); a cut past the cap warns
`job.section_overran`. `:danger` never waits; `do-now!` cuts at once. The outermost section is not opened while an entry
waits, so it fires in the gap. Urgent sections: door transit, table placement and craft, pillar climb.

**Waiting is never silent.** A check says why with `(ctx/wait ctx reason)` (a keyword or a map with `:reason`). The
scheduler emits one `job.waiting` when a check first declines and again only when the reason changes; it shows as
`:waiting` in `jobs show`/`list` and `observe`. A parent whose round returns a child's `:declined` keeps the child's reason, not told while that job's next round runs. A listed job that could start but waits behind a reflex job holding the body says `{:reason :reflex-holds :reflex id :job id}` (asked again every `held-recheck-ms`), gone when the reflex ends.

**List edits** (agent): `submit!` (appends; opts `:next?`, `:now?`, `:exclusive?`, `:survive-death?`, `:by`), `cancel!`, `retry!`
(clears a failed mark), `do-now!` (cuts the running listed job, sections or not, never a reflex, lists the new job directly before it as a
holder; the cut job continues afterwards with its memory). `:next?` lists the job directly after the current one so it gets
the very next round, without cutting anything.

**Persistence.** The list, register and changes are written to `engine.edn` on every change. On boot they are reloaded,
reflex instances are dropped, the in-flight job resumes first, and a `:restart` entry is appended. A register entry whose
saved args hold keys its job no longer declares is kept with those keys removed and raises a required attention request;
an entry whose trigger or job is gone is dropped with a `system.dropped` warn. A stop (SIGINT/SIGTERM or warm `stop`) first waits up to the `engine.main/danger-wait-ms` setting (15 s; `system.stop-waiting` logged) while a danger-level reflex runs; the signal handler exits after `shutdown-limit-ms` (20 s). `core/shutdown!` (SIGINT/SIGTERM) rotates
the token so the in-flight round is never booked; the job stays listed.

**Doing nothing.**
- `job.idle` (warn, once per spell): a round holds the body with no act in flight, no declared hold, and its last act (or
  start) more than `:idle-s` (10) ago. An act or clearing a hold ends the spell.
- `job.holding` (info): a declared hold (`ctx/hold-still!`, `act :wait` with `:why`); `jobs show` gives
  `:holding {:reason :since}`.
- `body.idle` (info, once per stretch; wakes `observe --wait`; memory `:body-idle`): no act but `:wait` from a job not
  `idle-ok` (stay-near, wait-for-light/-dusk) for `:engine.core.activity/body-idle-s` (10); lists each job with
  its `:waiting`/`:holding` reason. A useful act or a list change re-arms it. Under `--watch` (and `jobs submit --wait`) the wake lists only the watched jobs.
- Spin guard: a job that makes more than `:engine.core.round/spin-calls` (100000) engine calls (checks, writes, acts, `alive?`) inside one event-loop turn is failed with `spinning: job <id> ...` (it never awaited a timer, so nothing else ran).
- Stuck act: an act (primitive call) in flight longer than `:engine.core.round/act-max-s` (300 s; `:offline` plus its own time) is aborted: `action.stuck` (warn, names the act), the job fails with `act-stuck: <act>` and the body is free.
- `job.fruitless`: a required attention request when every act of a listed job failed in 3 rounds in a row (a round that
  ends the job does not count; a round with no act neither counts nor resets); resolved by a round with progress. It only flags.
- `job.silent`: a required attention request when a listed job got 5 rounds in a row over 180 s that did no act, held nothing and left no wait reason (runnable but idle); resolved by any other round. It only flags.
- `job.round_started` and `job.yielded` are debug; a job refused for bad args (can-start? :never :bad-args) starts no round.

**Backoff.** Register entries only: a reflex whose runs keep failing would fire as fast as the tick, so its entry waits.
Listed jobs are never backed off.

- `act!` classifies each act result: a status in `:engine.backoff/progress` (settings) is progress, one in
  `:engine.backoff/neutral` counts for neither, anything else is a failure. A `:backoff` declaration may move statuses:
  `{:progress #{"busy"} :failure #{..} :neutral #{..}}` (a status in one class only; a declaration also beats the
  walk `partial` rule; a status-only map never turns a `:backoff false` back on). `look`, `wait`, `equip` and `steer` are neutral. A walk round
  (`jobs.lib.near`) counts as one `:walk` act: `arrived` is progress, `partial` and long detours are neutral, a blocked
  walk is a failure.
- A **fruitless run** made no progress and every act failed, or it declined or stopped. Cut runs and throws do not count.
  The first progress act resets everything.
- Schedule `{:after 3 :first-s 1 :max-s 30}`: after `:after` fruitless runs the entry does not fire for `:first-s`
  seconds, doubling per further fruitless run up to `:max-s`.
- Config, most specific wins: engine `:backoff` < the trigger's `:backoff` in `triggers/defaults.edn` < the entry's.
  `false` turns it off (`:suffocating`, `:burning`, `:hostile-near`, `:night`).
- State is the non-persisted `:backoffs` atom, cleared after every pause (offline, settling, an exclusive run).
- Events: warn `reflex.backoff`, repeated at most every `:backoff-alert-ms` (300000); info `reflex.recovered`.

## Events and the local API

The engine writes one EDN map per line (`:debug` events not on stdout) to stdout and `worlds/<world>/agents/<name>/engine/events.edn`. The contract is in
`docs/event-stream.md`. Fields: `:seq`, `:generation-id`, `:time-ms`, `:source`, `:kind`, `:context` (job id, child chain,
round, reflex id, action-call id), `:data`, `:message`, `:attention` (omitted/`:none`, `:notice`, `:required`),
`:request-id`. Required attention requests stay in saved state until explicitly resolved. The log keeps 64 MiB across
`events.edn` and `.1` to `.3` (setting `:engine.events/max-bytes`, min 1024); `:debug` events go to their own chain `events.edn.debug` (+ `.1` to `.3`), kept `debug-max-age-ms` (3 h) and `debug-max-bytes` (128 MiB; about 35 MiB an hour on a busy body; `:job` debug events carry no position), and a hole in the seqs below the newest `:debug` event is no gap; a cursor is `{:stream-id :seq}` and a
rotated-away cursor gets an explicit gap. Start-up parses only each segment's first and last record, so its memory does not grow with the log. Only the newest 256 events (at most 256 KiB; settings
`:engine.events/recent-count`, `recent-bytes`) emitted since the start stay in memory; an older cursor reads the files, a page parsing about `max-page-bytes`; a line over `max-line-bytes` is not parsed, it reads as a stub with `:seq`, `:time-ms`, `:source`, `:kind`, `:level` and `:truncated`; an event's job id and chain are cut to `max-id-chars` and `max-chain` when written. Every `:engine.core.base/stats-ms` (60000) the body emits `body.heap` (`engine.heap`: V8 heap used, limit and total, rss, external, array buffers, in bytes; one key per gauge registered with `engine.heap/gauge!`: `jobs.lib.walk.search` registers the planner state kept outside job memory, `:known-cells`, `:known-edges`, `:goal-floods`, `:searches`).

A job that ends with a result of `:status :stopped` gets a `:stopped` warn event; its text is the result's `:text`, else `stopped: <reason>`.

## Exclusive run

An agent's "run this job now": `jobs.mjs submit --exclusive` / `world.mjs submit --exclusive` (`POST /jobs` op `:exclusive`, `core/exclusive-run!`). Online only, one at a time, no `:next?`/`:survive-death?`. It pauses the whole engine: the holder is cut at once (a listed job continues afterwards, a reflex job is dropped), no trigger or other job runs, and the job gets one round. Any ending ends the run and returns to the agent: `:done`/`:stopped` as returned, an error `job.failed` with attention (unlisted, not parked), a cut `:stopped :cut`, `:continue` or `:declined` `:stopped :yielded` (or the child's wait reason) plus the wait text, a failing check at once `:stopped` with the check's reason. Then normal scheduling resumes, except that no listed job starts for 5 s (`exclusive-grace-ms`, reflexes still fire) so a run of calls is not dragged away between them. Other jobs wait (`:waiting {:reason :exclusive-run}`), `do-now!` lists without cutting, a death cancels the run, a restart ends it `:restart`, `cancel` ends it. Not saved. `/status` shows `:mode :exclusive`.

- `world.mjs submit <move-to|dig|place|use-on|interact|equip|mount|dismount>` submits the job of that action (`go-to`, `blocks.dig`, `blocks.place`,
  `items.use`, `items.equip`, `movement.mount`, `movement.leave-vehicle`) with `:by` = `--who`; `--exclusive` makes it an exclusive run.
- `engine/js/control.mjs` is a stateless socket adapter for `body/control.sock` (mode 0600), which serves `GET /entities`.

```
node engine/tools/world.mjs ProbeDrive --world test submit move-to -5 64 -7 --who claude --exclusive [--wait --timeout 60s]
```

## Running a body: scenarios

A scenario is EDN read with `cljs.reader`:

```clojure
{:register [{:trigger :hungry}
            {:trigger :hostile-near :args {:radius 12}
             :job (jobs.survival.respond-to-hostile {:settings {:jobs.lib.danger/hostile-radius 12 :jobs.survival.respond.state/step 10}})}]
 :queue    [(jobs.movement.go-to {:pos {:x 10 :y 64 :z 0}})
            (jobs.time.wait-for-light)]}
```

`npm run body -- --agent <name> --world <world> --scenario <file>` loads `worlds/<world>/agents/<name>/config.json`
(`username`, optional `viewDistance` chunks, default 8) and `worlds/<world>/world.json` (`host`, `port`). It refuses to start when `--world` is missing, and with exit
code 3 when that body is already running (it binds `engine/body.sock` first). If `engine/engine.edn` exists the saved list
and register are restored (entries still `:by :scenario` or `:upgrade` are refreshed to the current default spec, keeping mute and place, one `trigger.refreshed` event each; agent edits stay; an exclusive run is ended, `cancelled` by `restart`, cut-off); `--fresh` discards saved engine state (memory is kept). `--warm` keeps the process after a stop: JSON lines on stdin (`{"op":"stop"}` answers `stopped` on fd 3, `{"op":"start","args":[...]}`) stop and start the engine in place; stdin closing ends the process (used by the world-test runner). The scenario is validated
before connecting; on a restart an unknown trigger in it is skipped with a warn and an attention request, and scenario triggers the
body never had are offered in one attention request: `triggers upgrade [ids]` adds them (`--upgrade` at start adds all), `triggers
decline [ids]` never offers them again; ids not in the offer come back under `:ignored` with a reason. Other flags: `--worlds <dir>`, `--blueprints <dir>`.

`survival.edn` lists the survival triggers and queues `(repeat (jobs.time.noop {:seconds 2 :why :idle}))`.
`woodcutter-cuts.edn` registers an ad hoc `:look-timer` condition to cut a long job on a schedule.
`test/engine/scenarios_test.cljs` runs `woodcutter` and `survival` end to end against the fake.

## Zones and claims

Zones (`worlds/<world>/zones.edn`) and claims (`claims.edn`) are a social rule that jobs consult. The engine never enforces
them: `act!` and the primitives check neither, and a job may ignore them. The helper is `jobs.lib.access` (`may?` for
`:dig :place :sow :harvest :take :put`) over the pure `jobs.lib.access.zones/verdict`. First match wins:

1. no zone list read: `:no-zones`;
2. the cell is in another active plan's footprint (the plan the job builds is left out): `:footprint`; a `:dig` in a `:kind :mineshaft` plan's footprint is not refused (it is shared; zones and claims still rule, and nothing is noted for tidy);
3. a zone holds the cell, its `:owner` is not the body (case-insensitive; `"unknown"` is foreign) and its `:allow` lacks
   the action (`:allow` is what others may do): `:zone`. The owner may always act;
4. an active, unexpired claim of another owner holds the cell: `:claim`;
5. else ok (`:own-zone`, `:own-claim`, `:open`).

- Query without a verdict: `jobs.lib.access/foreign-holder` (ctx, pos) names the zone, active claim or other body's plan holding a cell, else nil (nothing refused); `map.mjs --world W whose --center '[x y z]' --by ME` asks the same of zones and claims.
- Every job that digs, places or takes accepts `:ignore-zones? true` (default false). By default it skips a refused target
  with one warn naming the zone, claim or plan; a cell two plans share is such a target, and `:ignore-zones? true` acts on it anyway.
- `withdraw`, `deposit`, `haul`, `smelt` and jobs built on them wait `:refused` (`can-start?`/`can-run?`; a called child ends condition-failed `:refused`) on a foreign container.
- Survival jobs (`breathe`, `extinguish`, `shut-in`, the crop dig of `get-food`) prefer a permitted option and break
  another's block only as a last resort (warn `<job>.trespass-last-resort`); `get-food` takes another's crops only with the caller's `:ignore-zones?` plus real hunger, else its no-food text names what it left. They never take from a foreign container. A
  missing zone list never blocks a survival job.
- A plan's footprint is the body's own when its `:metadata :by` equals the body's username (case-insensitive).
- The farmland under a plan's crop cell is no cell of the plan (never a `:plan-cells` permission), but `jobs.lib.access/zone-input` adds it to `:footprints` (`world/soil-footprints`), so walks, stairs and cleanup never dig it.
- `access.stair` and `gather.mine` never dig a base block (chest, bed, furnace, table, door, sign: `rules/base-block?`), anyone's.
- A body's own plan never blocks its explicit work: `blocks.dig`, `blocks.place` and `access.pillar` act on
  its cells. `gather.mine`, `access.stair`, `access.clear-path`, `movement.go-to` (its escalation: stops `:own-build`; a body standing in another's zone, claim or plan leaves it by the way out without the zone refusing; a dig allowed warns `go-to.dug-own-build` per cell; it also spares the wall of the own pen, zone or plan, with livestock inside that the body is shut in, stop `:own-pen`; a pen not fully seen counts, jobs.lib.own-pen) and `forestry.fell-tree` spare own-plan cells unless the setting `jobs.lib.access/spare-own-builds` is false (default true; one setting for all of them, so a `:settings` override on a call reaches its children); `survival.dig-pocket` and `dig-in` always spare them. A stair never digs the block a door stands on. Acts that change no cell
  (animals, apiary harvest, compost, fertilize, sowing, sapling planting) also work in its footprint; till, path and mine place do not.
- **Tidying** (`jobs.lib.tidy`): a dig or place that breaks another's block is noted as a `:tidy` memory entry.
  `jobs.survival.restore-broken` puts the cells back when the body is safe; the `:tidy-pending` trigger starts it.
- **Placed items** (`jobs.lib.spent`): `tidy/place!` logs each placed block; craft (table), dig-pocket and retreat report `:spent {item n}`, `:spent-at` and a "used 7 oak_log (... at ...)" text.

**Base rates** (`jobs.lib.cost.base-rates`, pure; an input to costs): `(density resource pos biome body)` is the expected blocks of an ore (`"coal"`, `"iron"`, `"copper"`, `"gold"`, `"redstone"`, `"lapis"`, `"diamond"`, `"emerald"`) per block of ground at that height in that biome, 0 where the game places none; `(biome-chance biome pos body)` is 1 or 0 on ground the body has seen and an even prior over the ore-carrying biomes elsewhere; `(expected-density resource pos body)` weighs the first by the second.   tick by tick (a drop onto slime waits on the pad until the bounce settles, at most the fall's settle time plus 1 s; leaving the pad's slime cells is off the plan; a body on the ground inside scaffolding is not on a climbable for it, so it walks off a tower; with the eyes under water on a `:swim`/`:swim-down` step it swims, sprinting with the pitch toward the step, ~3.9 b/s, physics patch `tools/dependency-patches/swimming.mjs`; with the head out it paddles). `jobs.lib.near` (`walk-round!` for go-to, `go-near!` a walk to something visible as a go-to child that escalates when shut in, with `:leg-s`, `:look-round` and go-to `:one-way :closed` (default there: no drop it cannot climb back, no frontier walk): the forestry, farm, smelt, mine, build, apiary and animals jobs, and restore-broken; build, apiary and animals pass `:escalate false`, so they never dig through what they build, guard or fence; `build.from-plan` escalates only while the body stands in a hole 2 or more levels deep) opens and
  re-shuts doors via `jobs.lib.pass` (a button or lever it has not seen is looked at before it is worked; the iron door is turned to and read back; a walk that arrives in a doorway it opened steps to a cell beside it still in range, so the door is shut, `jobs.lib.pass/step-out-budget`); go-to's `:shut-also` shuts doors in or next to another owner's zone. Before the walker opens a gate it will shut, lure food in hand with its animals within 16 blocks is put away (`jobs.lib.bait`), so the animals do not follow through. The farm jobs' walks (till, plant, harvest, fertilize, compost, tidy) pass `:tolls` from `jobs.lib.toll-cells/walk-tolls`: the crops and farmland the body has seen near the walk and other owners' zone cells, crossed only when the way round is much longer; the zone cells over 8000 are cut to the ones nearest the straight line (a `toll-cells.capped` debug event). Zone-respecting jobs (every job with an `:ignore-zones?` arg that walks, e.g. mine, fell-tree, deposit, kit, bake, smelt, cleanup, from-plan, apiary, animals, rail) pass `:zone-tolls true` to `near/go-near!` or their go-to child. `jobs.lib.targets/nearest!` finds the soonest-reachable of many targets in one
  bounded, resumable search (used by `fell-tree` and `mine`).
- A search is bounded per round (about 100 ms) and resumable (a submerged body's falling air restarts it only once it fell more than 1 s, `jobs.lib.walk.search/air-drift`, its falling hp only past one 2 hp hit, `health-drift`; up to `kept-max` unfinished searches are kept per body, so another plan between rounds does not restart one); a search that needs more rounds walks toward where it has
  got to, or waits. A start closed in the loaded world, with the goal unloaded, ends `start-enclosed` (not `goal-unloaded`); a goal proved walled in or cut off while the start's own land is walled in too (a small forward drain, no cliff) ends `start-enclosed`. A dry body whose every way is a swim past its air (`air`, `air-lethal`) and whose dry cells are a pocket (water counts as a wall: `reach/room/dry-shut-in?`) escalates (stair, pillar) like a shut-in one. A goal that is lava, over lava or ringed by lava and read `goal-enclosed` is refused without any escalation (no dig makes it acceptable). An enclosed goal is found by a small backward flood before any walking (`goal-enclosed`, but with this body's ledger blocks within 3 of the goal, one `jobs.access.cleanup {:job :all :near}` child takes them back and the walk is planned once more; a region with a cliff edge, or an open-air edge to drop off at the goal's level (a pit inside walls does not count), says `goal-cut-off`, an island or deck, which go-to treats alike; `options.preFlood`, default 256 cells), and go-to keeps its flood between searches toward one goal (`goalFloodMemo`).
- A partial plan ends at the node nearest the goal that the body can come back from (one-way drops, gap jumps and ways into a
  downward bubble column above its bottom are not taken), walked only to its last step with the head out of water. `go-near!` never leads the body off a ledge it cannot climb back.
- A route never ends on magma or in a magma bubble column: a goal with no other cell in range ends `goal-on-magma` before any search, and go-to gives up at once.
- Under go-to's `:see` a goal whose in-range stands none sees the block ends `goal-unseen` before any search (go-to: `:exhausted`, then `:out-of-sight`), not after flooding the loaded land to the node budget.
- A search that runs out of loaded land names a frontier (a loaded edge) at most `options.frontierReach` (256) farther from
  the goal than the start. go-to tours frontiers until every one is spent, walking land it has searched once (its searches stop
  at the first edge, then expand as many nodes again or to the round's budget, so land they read stays known once it unloads;
  each chunk holding a node they left unexpanded keeps one edge open), or until the tour since it last came nearer the goal
  costs more than the goal is worth (`jobs.lib.cost/tour-cost` over the `:tour-worth` setting, else the call's `:worth` (seconds the caller counts arrival worth; get-food passes `cost/food-worth`) less the trip and the straight walk, else `tour-worth` of the straight
  distance: a trip and `:tour-ratio` (3) times the walk of at least `:tour-floor-blocks` (32) blocks; `:per-frontier-walk` too is an option): `:explore-spent`. `:worth` also sets the route risk go-to's start check accepts (`jobs.lib.price/allowed`: the hp that worth buys at the price of an hp, all but 1 at most; a small worth refuses a dear trip, no worth: `::risk-share` of the health). cleanup passes `::worth-hp` x hp-seconds per scaffold block.
- A masked go-to search that ends `:budget` with no progress switches the call to an edge tour (mem `:edge-mode`, info `go-to.edge-tour`): the mask reads unseen cells as loaded edge (`unknown.edge`: UNLOADED, no `options.unknown`, `hasColumn` false), and a frontier is any node with an unseen cell beside its feet or floor (`inBand`, `atLoadedEdge`), so the body walks to the edge of what it has seen, looks, and replans.
- The walker watches the way ahead and replans when the world under the plan changed, when a mob blocks a leg (stuck, or standing 1 s in a 1-wide way ahead), when the hp planned for drops ahead is over what it may spend now (`:health`), and every 4 s
  for a partial plan. A fall that costs over 1 hp more than planned is a `damage-mismatch` warn.
- A running gap jump (over 2 or 3) onto a landing with no wall past it and a fall there that reaches `options.health` (an unseen or unloaded cell in that column counts as deep) is refused: it overshoots a one-cell landing. A gap jump over a hole whose short fall reaches `options.health` (an unseen depth counts deep) adds `costs.gapMiss` (0.02, go-to `:costs :gap-miss`) times a death's price as risk: it is jumped only when no other way gets there. No gap jump leaves a tight cell (within a block of a fence) except over a gate or door cell; a shut gate it crosses is opened first (the opening pass).
- A drop lands only in water that holds a fall: not falling water (a waterfall), and held up by a floor or by water that is not falling.
- Risks are priced rather than banned: gap jumps over pits, corner slides over lava or fire, time near known dangers
  (`options.dangers`: every sensed mob (`:block true`) fills its cell, which no plan enters, and a partial plan ends out of the hostile-near radius of one (`walk/plan stop-short`; a body already inside walks back along its way first, `walk/back-off!`); every known threat (`threats/known-threats`: a melee mob with no way to the body, at the foot of its pillar, counts; `:threat` spots are dropped once the client no longer tracks the mob, through `threats/listed-threats`) tolls its field (`threats/threat-tolls`),
  dear when the hostile reflex would flee the mob, cheap when it would fight; a newly sensed mob whose field holds a step ahead replans the walk; `go-near!`
  `:dangers false` for a walk up to an animal; a `:hostiles` fight's walk prices them and falls only within the damage budget less the fight, `attack/fall-room`). Darkness is priced too (`options.dark`: an unarmed body pays a dark cell twice a lit one, an armed one less; `jobs.lib.look/dark-fn`: seen and dark, or unseen at night). The caller's own cells are priced by `options.tolls` (a Map of cell key to factor; the planner knows no zones or crops). Certain damage (falls over 3 blocks, hurting plants) sums per path: `options.damageBudget` (hp) refuses a move over it (`damageRefused`), `damageWeight` prices an hp, `fallFactor`/`landing` shape a fall; `cost.damage` reports it. Farmland is never fallen onto: no drop or gap jump lands on it, and no diagonal
  passes a pit floored with it. The planner
  takes `options.limits` for what the walker can do.
- `options.unknown` (go-to `:unknown`, on by default; a masked plan swims on only while the way out and back to its last breath, each move at its measured pace (a level swim of a body that does not sprint at swimH, as the planner), leaves the air margin (`jobs.lib.cost/wet-ok?`, settings `wet-pace`, `wet-margin-s`); a walk under water past that margin, whose swim outlasts the air left or surfaces at an unseen cell, ends `:air-spent` (drive/follow!), go-to swims back to the cell it last breathed at (mem `:last-air`) and escalates): void_air cells are unseen, air to the body but never breath (a swim in water under one drains the air like a dive; a walk looks up at the first unseen cell over a dive's head before it swims on) (seagrass, water, while the head is under water: a plan to air also ends at an unseen head cell); a stand on an unseen floor is allowed only after a move the walk can stop before and where it can be seen (`seeDepth`, `seeLit`, or a torch: `lightCost`, step `light`), else `darkRefused`/`darkBest` or `unseenRefused`; priced and depth-limited (`seeLitDepth`, `lightDepth`) by `jobs.lib.cost/unknown-prices`; no proof rests on an unseen cell.
- Every walk's steer glances behind it (`jobs.lib.walk/glance-ticks`, default every 10 ticks, 0 off): the head really turns for one tick (behind, left, behind, right in turn; the movement keys are remapped with it, `turn-controls`, so the walk keeps its way; no glance in water, on a climbable, at a jump or sneak, or toward a known enderman), the next tick takes a mob sample (`knownMobs`) and the head goes back, so a silent creeper behind a walking or fleeing body is seen and feeds the usual danger path.
- The floor gate (`jobs.lib.walk.sight`, on only for a plan over a masked snapshot, whose steps carry `:unseen-floor`): the executor gets the steps up to the takeoff of the first floor still unseen; the walk glances at that floor each tick and a stop controller (prismarine's own physics) holds the body at the takeoff's edge, looking at it (a body stuck on the way still ends `:stuck`). Seen plain: walk on; seen otherwise: `:replan :changed` once the body is out of the air (a jump lands first; a body still moving brakes first, at most 20 ticks, else its slide carries it off the takeoff); still unseen once still: `:replan :unseen`, the floor joins the mask's `missed`, or, on a `:light` step, the walk places a torch and looks again (the takeoff joins `noLight` when none goes there or the floor stays unseen); a body on it anyway (a push): `:replan :pushed` and a `gate-breach` warn. After a floor seen as not there, `drive/follow!` looks at the unseen ground round the body once (`look-over-edge!`; setting `::look-over-edge`, off for `run-away`) before planning again, and counts learned replans against `max-watch-replans` past the sixth, so a void edge ends the walk instead of one search per column; the `max-learned`th learned replan (walk.watch setting, 8) ends it `:learn-spent` and go-to gives up `:unseen-floors` naming the cells. Debug events `walk.gates` (the walked steps and their `:unseen-floor` flags) and `walk.gate-resolved` (the block that resolved each gate). Physics bench: `test/engine/walk_gate_physics_test.cljs`.
- Landing look (`jobs.lib.walk/walk!`, any plan): a leg ends at the takeoff of a drop of 2+ whose landing or the cells beside it (feet and head level, 3x3) are unseen; the body looks at them, and lava in the landing or orthogonally beside it ends the walk `:replan :changed` (lava only diagonal does not); the planner then prices the landing and may still take it. A dig walk (`dig-for/walk-to-dig!`) tolls the goal stands beside seen lava (`dig-for/lava-side-toll`), so another stand is taken when one reaches the ore.
- The mask: `jobs.lib.walk.world/path-world p spec` (`unknown-spec`, one `missed` and one `noLight` Set per go-to call) has `js/path/live-snapshot.mjs` read every cell the body never saw or felt (perception memory) as void_air (seagrass with the head under water), known cells live; under ground (no sky light at the feet, head out of water, not the edge tour) a cell never seen more than `jobs.lib.walk.world/rock-beyond` (3) blocks from every seen open cell, the feet and the goal reads stone (`jobs.lib.walk.rock`; an unseen cell straight above a seen climbable, through unseen cells only, is a shaft and stays unseen, and the planner climbs it, up or down, even when unseen cells read as water), and a go-to whose search then runs out of land digs toward a goal no higher than it is across (higher: a stair) (`dig-route`, legs of up to 6 blocks along the line while the call's dig seconds stay within `:worth`, else its job time left; `:dig-budget`); a swim-down onto a floor or swim-up into a roof it took for water ends the walk `:replan :changed` at once and blocks that cell (`walk/felt-solid`); progress distance counts height for a near goal; the snapshot carries the planner's `options.unknown` (prices, `seeDepth` from the hands' near (`jobs.lib.walk.sight/see-depth`), `seeLit` `jobs.lib.look/see-lit-fn`) through every `with-*`, the watch's fresh world and the kept searches' keys. A masked search holds at most `jobs.lib.walk.world/unknown-max-nodes` (12000) nodes and then ends `:budget` (no search without the limits follows it): a goal no seen route reaches otherwise floods unseen cells to the 200000 limit. The goal flood leaks on an unseen cell only where a way could pass: a seen whole block ends a climb, fills its cell and leaves no stand under it, a diagonal step passes no corner of two seen whole blocks, and a jump or drop crosses only free columns, so a seen closed room is proved walled in whatever lies unseen outside it.

## Agent command-line tools

All take `<body> --world <world>`, print EDN, read through the local sockets, and never start a body unless
noted. Most run a prebuilt bundle: build it once with `cd dashboard && npm run build-agent-tools`. The loader warns on stderr when a source is newer than the bundle: rebuild with `tools/compile dashboard agent-tools`.

```
node engine/tools/observe.mjs Bob --world test                       # compact status (--raw: full snapshot, --verbose)
node engine/tools/observe.mjs Bob --world test --wait [--timeout 30s] [--watch j17]
node engine/tools/observe.mjs Bob --world test job j17 | result j17
node engine/tools/observe.mjs Bob --world test events [--until death] [--kinds died,hurt] [--job j17] [--level debug] [--since 10m] [--before SEQ] [--limit 20]   # past events, newest page first, oldest first within it; :next-before pages back; a post-mortem is `events --until death`
node engine/tools/observe.mjs Bob --world test catalog jobs [--all] | catalog jobs jobs.farm. --limit 10 | catalog job <name> | catalog trigger <name>

node engine/tools/observe.mjs Bob --world test light [x y z] [--radius 0-8]   # perceived light at a cell (default the feet): block, sky, sky-subtract, effective, lit/dark, seen
node engine/tools/observe.mjs Bob --world test settings [--changed] [--raw] | settings reload | settings set :jobs.x/key <edn> | settings unset :jobs.x/key   # keys with layer and the game rate; dashboard popup has the same
node engine/tools/entities.mjs Bob --world test [--type zombie --radius 32 --player Alex --limit 20]
node engine/tools/jobs.mjs Bob --world test list | show j17 | cancel j17 | cancel-all | retry j17 | resolve <attention> --reason handled
node engine/tools/jobs.mjs Bob --world test submit '(jobs.movement.go-to {:pos {:x 10 :y 64 :z 20}})' [--next|--now|--exclusive] [--alongside] [--wait --timeout 5m]
node engine/tools/triggers.mjs Bob --world test list | show hungry | upgrade [ids] | decline [ids] | add hungry --trigger hungry | mute hungry --for 10m | unmute | move X --before Y | reset X --property position | remove X
node engine/tools/triggers.mjs Bob --world test put near-home --when '(< (inventory "bread") 8)' --job '(jobs.movement.look-around)' --persistence cooldown --cooldown-s 30
node engine/tools/say.mjs Bob --world test [--to Steve] "message"       # chat, shares the engine's rate limits
node engine/tools/snapshot.mjs Bob --world test [--yaw 90 --pitch -20 --look-at X,Y,Z]   # PNG of its view: draws its seen entities, prints :heard and :light; a torch held in either hand lights it (14, less 1 per block)
node engine/tools/time.mjs --world test clock | dawn --timeout 1200   # world time from a fresh observer pose (the workspace wrapper adds --body: that body first; Probe* world-test bodies are read only by a Probe* asker)
node engine/tools/goal.mjs Bob --world test ["fence the pen" [--by NAME] | --clear]   # the goal line the dashboard shows (agents/Bob/goal.edn)
node engine/tools/progress.mjs Bob --world test [--goal j14] [--want iron_ingot:24,iron_pickaxe] [--wait 60m [--stall 10m]]   # one check-in line; --wait returns only on goal end (reported once: the saved goal is then dropped), death, a give-up, needs-you (also a body idle with only idle-ok jobs left, or hp 4 or less) or a stall; those three wakes also print SNAPSHOT <path>: a picture of what the body saw (workspace snapshots/warn-*.png, drawn by the tool after touching the body's view watch marker; one per reason per 5 min)
```

Every workspace `bin/` call appends a `:start` and an `:end` line (tool, argv, observer, exit, `:wake` of a wait) to `worlds/<world>/agents/<Body>/logs/tool-calls.edn`; an `:end` is missing while the call is open.

- `observe --wait` blocks until addressed chat, new attention, a watched job or action finishing, `body.idle`, an engine restart or the
  timeout (default 60 s). Each named observer (`--observer`) keeps its cursor in `worlds/<world>/observers/<body>/`; delivery
  is at least once. `--chatter none|addressed|all` and `--disconnect` choose what wakes it; a hit on the body always wakes every agent-tool wait (`observe --wait`, `jobs/world submit --wait`, `progress --wait`) unless `--no-danger`. Each wait reply carries `:vitals` (`:hurt` first when health fell during the wait, `:health`, `:food`, hostiles seen/heard near, and the reflexes-off reminder under a manual take); `drive` replies repeat that reminder. Only the first `reconnect-failed` of an
  outage wakes it (later tries are summarised). Status of an offline body adds `:back-in-s`. A `died` wake or summary item carries `:cancelled-jobs [{:id :name}]` (jobs the death cancelled, seen in the same call).
- `jobs.mjs show jID` of a job the scheduler no longer holds answers from the event history, as `observe job` does.
- `jobs.mjs submit` of a plain job call is held back (exit 1, `:reason :job-clash`, `:clashes`, `:hint`) while a job of the same name, or any two of mine, stair, tunnel and strip.* jobs, is running, queued or resuming on the body; `--alongside` overrides, a `(repeat ...)` or combinator spec is never held (tool only; the engine accepts both). The job list is read with 3 tries; if unreadable the submit is refused (`:reason :clash-check-failed`, nothing queued).
- `jobs.mjs submit` appends to the list; `--next` lists after the current job without cutting; `--now` cuts the current
  listed job and runs the new one next as a normal job; the cut job continues right after it yields or ends (a running reflex is not cut); `--exclusive` runs it alone with the engine paused until it ends (see Exclusive run); `--survive-death` keeps the job listed through a death (it runs again after the respawn reflexes); a `(repeat ...)` spec gets it by default. `--wait` blocks until the job ends (or a wake) and prints the result and a bounded summary. Mutations carry a
  request id (`--request-id` to retry safely); the engine keeps the latest 128 ids and a duplicate returns the original
  result.
- `triggers.mjs` uses `GET/POST /triggers`; built-ins cannot be replaced or removed, only muted or moved. `put`/`add`
  replace a custom entry and reset its condition, latch, cooldown and backoff state.
- `entities.mjs` reads the body's perception cache (hostile mobs list first, heard ones too, then nearest first; a row has the numeric `:id` when known; `:sense` is `:seen`, `:heard` or `:remembered` (also a seen row no sample has refreshed for 3 s); a `:heard` row has no `:pos`, only `:direction` (8 compass points)
  and `:band` (`:near` within 8, else `:far`); rows older than two minutes expire). Engine reflexes do not read it.
- `world.mjs` submits one body action as a job (see Exclusive run).

### Plan, blueprint and map tools

`plans.mjs` (one world's plans), `blueprints.mjs` (global blueprints), `map.mjs` (markers, zones, claims) and
`world-changes.mjs` (a change feed) work directly on world files and need no body or dashboard. They require `--world`,
return EDN, cap pages at 10 records (100 with `--limit`, `--offset` pages on), and take `--raw`, `--dry-run`.

```
node engine/tools/plans.mjs --world test list | find home | show home --raw
node engine/tools/plans.mjs --world test validate home --edn '{:id "home" :parts []}'
node engine/tools/plans.mjs --world test check home --body Wren --inventory '{:stone 24}'     # material needs and conflicts vs what that body has seen (its seen memory, in the plan's `:dim`, default overworld; `add` by a body stamps its current dimension); never-seen cells count unknown; `validate` and `check` list `:warnings` for a door that opens onto a part-height block (bed, bottom slab) under a full block planned two above, where the body cannot step on (minecraft-data collision boxes)
node engine/tools/plans.mjs --world test add|edit home --edn '...' --by builder [--revision <digest>]
node engine/tools/plans.mjs --world test mineshaft pit --at=0,64,0 --heading east --to-y 16 --by digger     # declares a stair shaft plan (:at = feet cell of the top step); show names its depth and heading, check counts its steps dug/undug/unseen
node engine/tools/blueprints.mjs --world test find hut | show starter-hut | validate hut --edn '...' | save hut --edn '...' --by builder [--revision <digest>] | remove hut --by builder --revision <digest>
node engine/tools/map.mjs --world test find --type marker --text farm
node engine/tools/map.mjs --world test add zone garden --by Alice --data '{:min [10 63 20] :max [20 70 30] :allow #{:harvest}}'
node engine/tools/map.mjs --world test add zone hut --by Alice --box 10,63,20:20,70,30
node engine/tools/map.mjs --world test add claim extension --by Alice --for 30m --data '{:min [21 63 20] :max [30 70 30]}'
node engine/tools/map.mjs --world test renew|release|remove claim extension --by Alice --if-revision REV
node engine/tools/world-changes.mjs --world test --wait --type claim --observer planner --timeout 30s
```

- Mutations are atomic compare-and-swap writes under a shared lock. `add` creates only; `edit` and `remove` need the
  digest/revision shown by a read, so stale intent is refused. Mutations require `--by`.
- Plans have no status: every submitted plan is active and takes part in conflicts and footprints; `remove` deletes it.
- Claims are authored social intentions (default 30 minutes, 100 ms to 7 days). An active claim overlapping another owner's
  is refused with the conflicting ids. Only the owner may renew, release, edit or remove one. Claims do not authorize
  anything; jobs consult them as above.
- Markers keep the `places.json` format; zones use the strict `zones.edn` schema.
- `world-changes` keeps a named cursor outside engine state and returns grouped changes (latest 2048; `:cursor-gap` after loss).
